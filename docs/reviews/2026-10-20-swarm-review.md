# Repository swarm review — 2026-10-20

## Scope and decision

Twelve specialist source reviews covered architecture, frontend state, UX, accessibility, styling, persistence, security boundaries, performance, desktop behavior, testing, settings contracts, and navigation. A single judge read all twelve numbered reports in `artifacts/swarm-review`, inspected the cited production paths independently, and accepted twenty-six findings while deferring six. Base: `c088337f`; working branch: `codex/swarm-review-improvements`. Remaining deferrals have specific lifecycle, concurrency or resource-policy risks.

The PR addresses reliable local operation and recovery: preserve project ownership and user input, restore broken navigation and visual affordances, and make the default SQLite/runtime verification paths behave correctly. Protected integration/OAuth/token-encryption files remain outside this scope. Agent spawning/recovery contracts are deferred, so their three-document synchronization requirement does not arise in this scope.

All thirty-two reported findings have a disposition below: 26 ACCEPT, 6 DEFER, 0 REJECT. ACCEPT means implement and test in this PR. DEFER means supported by inspection but requiring a larger coupled lifecycle/concurrency change or an unresolved resource policy, with that reason identified. REJECT would mean incorrect or inadequately supported: no complete finding met that threshold. This does not endorse every suggested implementation or severity statement.

## Independent validation

- Inspected all cited core implementations, including SQLite scheduling/binding, singleton Sketch reducers, ProjectShell lifecycle/synchronization, WebSocket ticket continuations/handlers, feedback callbacks, delivery mutations/status, shared modal hooks, theme configuration/typography, desktop HTML injection and bootstrap guard, command route composition, semaphore/recovery/settings paths, and resource limits.
- Ran the built SQLite adapter against controlled database stubs. `SELECT $2 AS a, $1 AS b, $2 AS c` produced three `?` placeholders with only the original two parameters; a scheduled synchronous `prepare()` error reached the process's `uncaughtException` handler rather than rejecting the query promise. The probe used a dedicated Node process and changed no database.
- Compiled a Tailwind/PostCSS fixture with the repository's installed configuration. `bg-theme-bg` and `text-accent-primary` emitted CSS; `bg-theme-bg/90`, `hover:bg-theme-info-bg/50`, and `text-theme-accent` emitted none.
- Reproduced Windows CLI behavior: the affected-workspaces CLI returned status 0 with zero stdout for `--all --json`; the frontend Vitest wrapper returned status 1 with zero stdout/stderr for `--help`.
- Other findings are independently traced source defects, not claims of runtime/browser reproduction. Reviewer severity labels are prioritization estimates. In particular, security observations use the app's existing single-user local trust model, not a multi-tenant authorization claim.

## CI repair and local verification gap

The original PR's CI test job failed before running tests: its depth-one checkout contained the PR and base refs but lacked a visible common ancestor, so `git merge-base origin/main HEAD` exited 1 during affected-workspace selection. The other four jobs passed. Local verification had used a complete-history repository and forced-all CLI probes; `--all` bypasses Git comparison. The ordinary merge gate also does not run the separate coverage job's workspace-selection step. The initial tests exercised file mapping and CLI launch, without recreating CI's shallow Git history.

CI now fetches full comparison history. The selector also conservatively selects every workspace when an existing ref has no available merge base, preserving test coverage instead of crashing or skipping work. A real-Git regression in the standard shared suite creates divergent branches and depth-one clones, verifies the missing common ancestor, and exercises GitHub, explicit-base, and local-default selection paths. A complete-history fixture verifies precise frontend-only selection. These tests do not bypass selection with `--all`.

The verification guide now requires both the ordinary merge gates and `npm run test:coverage:affected`, with an explicit selection preview and verification of every required CI result. Unavailable prerequisites remain incomplete validation. No coverage thresholds were lowered or tests disabled.

The local noise identified during the initial QA was also repaired: CSP hashing tests normalize HTML line endings as a browser does; test-report paths use portable forward slashes; and the saved-feedback timer is cleared on unmount, including saves that finish after unmount. Regression tests preserve CSP hash checks, summary contents and save behavior.

Post-repair local results: build and lint pass; all 461 shared tests pass with coverage (98.03% statements/lines, 90.23% branches, 98.75% functions); all 3,178 frontend tests pass across 207 files with exit code 0 and no teardown error. The default affected-coverage entrypoint selects all four workspaces and correctly reports the missing local PostgreSQL test database.
